# apps/mobile

Expo (expo-router, React Native, Uniwind). Uses the same `@repo/client` hooks and
`@repo/i18n` catalogs as web; its UI primitives are its own, in `src/components/ui/`.

## Commands (from the repo root)

- Start Metro: `bun run --filter @repo/mobile dev` (API at `EXPO_PUBLIC_API_URL`)
- Unit tests (Jest, not Vitest): `bun run --filter @repo/mobile test`
- Types: `bun run --filter @repo/mobile check-types`
- E2E on the react-native-web build: `bun run test:e2e --app mobile`
- Native flows (dev build on a simulator): `maestro test apps/mobile/maestro`
- Dependency health after an Expo upgrade: `bun run --filter @repo/mobile doctor`

## Where things are

- `src/app/`: routes. `_layout.tsx` guards `(app)` and `(auth)` with `Stack.Protected`.
- `src/lib/api.tsx`: `ApiProvider` setup (absolute base URL and session cookie header on
  native). `src/lib/auth-client.ts`: better-auth with the Expo plugin and SecureStore.
- `src/lib/config.ts`: the only runtime config (`EXPO_PUBLIC_API_URL`, validated with
  zod). There is no `src/env.ts`; build-time values are in `app.config.ts`.
- `eas.json`: build profiles `development`, `preview`, `production`, one channel each.

## Gotchas

- `EXPO_PUBLIC_*` values are compiled into the app and visible to anyone. Never put a
  secret there.
- Installed apps outlive releases: the API must keep serving old builds. A breaking API
  change needs `MINIMUM_CLIENT_VERSION` raised, which sends old apps to
  `update-required`.
- `uniwind-types.d.ts` is generated by `bun run gen`; do not edit it.
- Message keys are not type-checked here as they are on web; check the key exists in
  `packages/i18n/messages/en.json`.
- `ios/` and `android/` are generated by prebuild and not committed.
